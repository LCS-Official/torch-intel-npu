# 当前 decoder 热点复测与 KV 位置标记融合

2026-10-10，Core Ultra 7 258V / Lunar Lake NPU 8086:643e，驱动 32.0.100.5540，编译器 8.3。
PyTorch 2.14.1+cpu，SmolLM2-135M-Instruct，既有 npunlock 原生后端，无新增依赖。

本轮完成当前版本的原生阶段与 FP16 / W8A16 设备热点复测、共享 KV 选中标记候选、
六组模型对照、真实生成和正式接入。修改已进入默认 SmolLM decode 图，无需用户开关。
真实生成 FP16 66.16→71.56 token/s，W8A16 70.87→73.01，均 7/7 轮更快。
全部 32 步 logits / token 逐位一致，正式 74 项模型回归和最终离线审计通过。

## 先测量当前基线

基线已包含上一轮的精确 RMSNorm 编码、共用 RoPE / 掩码 Gather，以及 256 块分配缓存。
复用指纹匹配的隔离诊断 DLL，未覆盖旧实验目录或修改正式 runtime。
普通图原生阶段采样各 62 次，范围为驻留 30 层 decoder，不含 CPU 输出头与边界传输。

| 普通图原生阶段中位数 | prefill，ms | decode，ms |
| --- | ---: | ---: |
| 整个 decoder 调用 | 19.370 | 12.528 |
| fence 等待 | 12.298 | 9.379 |
| 提交 | 1.425 | 0.925 |
| 参数绑定 | 0.236 | 0.230 |
| 原生计数器覆盖之外，约 | 4.903 | 1.836 |

decode 为 30 次 append、300 次绑定、8 次提交 / 等待；预热驱动分配和释放均为零。
不同项中位数不能严格相加；计数器之外还含 C++ 验证、锁、Python 等，不能全部归为 Python。
等待包含设备执行、排队及未单独记录的搬运，不是纯 DPU 算时。

## 修改与实际任务变化

原 decode 已按位置一次 Gather 取得 RoPE cos / sin 和因果掩码，但 KV 更新仍计算
`Equal(slots, position)`，再用两个 Select 复制 K / V。
现在把 FP16 的 64×64 单位矩阵追加到联合位置表，同一次 Gather 取出对应的 0 / 1 行，
转换为布尔选中标记。有效整数位置 1..63 的标记与原 Equal 完全一致。
K / V Select、旧快照只读规则、下一个位置的精确增量及模型算术均保留。

四层独立设备采样，每张普通 / profiling 图输出和缓存逐位一致，共 48 份新任务记录。

| FP16 每层 decode 任务数 | 原图 | 共享标记图 |
| --- | ---: | ---: |
| SHAVE 总数 | 86 | 74 |
| Equal | 12 | 0 |
| Convert | 1 | 1 |
| Gather | 1 | 1 |
| Select | 16 | 16 |
| DPU 总数 | 96 | 96 |

编译器没有因布尔转换新增 Convert 任务。四层 SHAVE 区间并集之和的三样本中位数
为 1.231→1.162 ms；DPU 为 0.111119→0.111059 ms，未修改其投影工作量。
这些是独立 profiling 观测，实际收益以普通图配对计时为准。

联合表从 192 列变为 256 列，原始表额外占 8 KiB。
该层 B1 FP16 decode 的序列化常量净增 8,112 B，编译 blob 7,764,304→7,736,144 B。
正式修改只在 `torch_npu_smollm.py` 的 `graph()`；内核 C / ELF、原生 DLL、设备扩展、精度和量化策略均未修改。

## 真实生成与默认接入

30 层 decoder 全部在 NPU；CPU 保留 embedding、最终 norm、lm_head 和 argmax。
B1、24-token 提示词，固定生成 32 token，不提前停止 EOS。
7 轮 ABBA / BAAB 对照，每版本 14 次生成；两版共享 prefill 图，均使用默认 group4。
样本标签 `1` / `4` 代表原 / 新图，均不是 group_size=1；图选择和候选编译在整次计时之前完成。

| 模式 | 原→新耗时，ms | 吞吐，token/s | 吞吐增加 | 更快轮数 | 首 token，原→新 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| FP16 | 483.697→447.172 | 66.16→71.56 | 8.17% | 7/7 | 23.290→23.108 |
| W8A16 | 451.558→438.271 | 70.87→73.01 | 3.03% | 7/7 | 23.034→23.365 |

计时覆盖 CPU 阶段、上传下载和 NPU decoder；最终状态销毁及数值验证在计时之外。
全部 32 步 logits / token 逐位一致，每次 960 次图调用、930 个 decode chain 图、248 个 chain 分组。
两版预热后均无新增驱动分配或 session，显式上传 / 下载各 32 次。
CPU 阶段也有波动；后台负载和频率未锁定，不将全部吞吐差异归为单一设备任务，也不与旧实验增益相加。
prefill 图没有改动，W8A16 首 token 本轮略慢，不能保证所有阶段均提速。

接入后用无候选替换的正式默认图，各精度另外确认 8 次生成，全部 32 步输出与隔离基线逐位一致，预热分配为零。
这组确认的两个标签实际都使用同一默认图，不作为第二组新旧性能对照。
正式 8 组回归共 74 项通过，覆盖归一化、数值、边界、保护、因果性、混合路径与堆叠模型。
全部正常进程退出后，context 健康，live / cached / quarantined 内存和会话归零。

## 余下目标与复核

共享标记图的四层采样中，RMSNorm 仍约 0.601 ms，对照全部 SHAVE 约 1.162 ms；
Multiply 约 0.189 ms、SHAVE attention MatMul 约 0.134 ms、Select 约 0.116 ms。
下一步更值得继续细查 RMSNorm 的 FP16 解码、FP32 归约和两次精确舍入流水线，保留完整模型和精度门槛。
当前结果不支持继续通过增加空闲缓存容量改善已测流程，也没有证明模型受 DPU 峰值算力限制。

FP16 首步 logits 对 CPU FP16 的相对 L2 误差仍约 0.484%；W8A16 仍约 5.69%，超过既有 3% 门槛。
本轮新旧逐位一致，不代表量化质量问题已修复；未重跑通用训练全集，也未增加 64-token 以外的模型能力。

`before/`、`torch_npu_smollm-after.py`、`promotion.json` 保存正式修改前后文件和指纹。
`position-flags/` 保存六组模型对照、独立 profiling 和生成；`production/`、`regressions/` 为正式确认与回归。
`runners/` 保存复用协议源码，修改前审计及其源码单独保存；本轮证据约 108 MiB，没有复制模型权重或整套模型 blobs。
