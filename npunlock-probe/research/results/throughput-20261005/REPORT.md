# 当前 NPU 矩乘吞吐实测 — 2026-10-05

本轮测量当前源码和已保存 ELF，没有修改或重新构建生产内核。结果为当前执行路径的有效矩乘吞吐，不是硬件理论峰值，也不是设备时间戳测得的纯计算时间。

平台：Intel Core Ultra 7 258V / Lunar Lake NPU 8086:643e；驱动 32.0.100.5540（1005540）；已验证的编译器 profile 8.3；PyTorch 2.14.1+cpu，PrivateUse1 intel_npu。使用现有 .conda/npunlock 环境，无新增依赖或 OpenVINO runtime。

## 计时与操作数

- 有效操作数为 `2*M*K*N`，一次乘法和一次加法计两次操作。TFLOPS/TOPS = 有效操作数 / 秒 / 1e12。
- 只计算一次逻辑矩乘，不把八个 SHAVE 输入副本当成八次矩乘；补零、补偿求和、量化、打包等辅助工作不增加分子。
- 原生绑定：输入、输出预分配，使用现有 C++ `run` 入口，一次图执行。排除编译、输入上传、数值校验及输出下载，包含图 DMA、驱动调用与完成 fence。
- 图接口：同一输入和编译图，使用现有 Python `npu._run`，每次重新分配输出。也排除编译和上传/下载。
- 每个路径预热 5 次。DPU 以及 SHAVE 单图各 31 轮中位数；完整 FP32 Torch API 各 11 轮中位数。DPU 精度路径轮换顺序，原生绑定和图接口在两个连续阶段分别测量，不能把它们的差值当作精确的分配成本。
- 桌面负载、电源设置和频率未锁定；原始样本及四分位数保存在 JSON。这不是受控硬件峰值认证。

### 精度和计算路径证据

编译后检查所有非逐元素 DPU invariant：FP16 要求 `(amode,wmode)=(0,0)`，W8A16 要求 `(0,2)`，W8A8 要求 `(1,1)`。这 15 个图全部满足要求。W8A8 实际是零点 128 的 U8×U8，表达有符号 INT8 量化值；不是只有权重文件为 INT8 而计算仍使用 FP16。

使用随机非零整数网格输入/权重及二进制精确 scale，三种路径处理相同逻辑矩阵。全输出与 CPU 参考比较，同时对首行、中间行、末行使用独立 NumPy INT64 点积参考。15 组输出相对误差均为 0。此网格适合验证计算路径与吞吐，不代表任意模型量化误差为 0。

DPU 矩乘任务由已有 Intel 驱动编译器生成。这里测到的是项目经该编译器执行 DPU 图的性能，不是全新手写 DPU 指令内核的性能。

## FP32 SHAVE 实测

FP32 保留当前乘法、分离加法、Neumaier 补偿以及特殊值处理约定，没有把计算降为 FP16。

### 八任务直接矩乘单图

| M/K/N | 中位数 ms | 有效 GFLOPS | 有效 TFLOPS |
|---|---:|---:|---:|
| 32/64/32 | 3.9538 | 0.03315 | 0.00003315 |
| 64/128/64 | 16.6501 | 0.06298 | 0.00006298 |
| 56/256/64 | 28.7059 | 0.06392 | 0.00006392 |

计时包含八份完整输入副本对应的图内 DMA；输入副本及输出已预分配。每个 SHAVE 只计算自己所属行。计时不包含后续行选取/完整输出合并，因此这个值比完整 API 更接近当前计算图的吞吐，但仍不是纯 SAU 指令吞吐。M=56 用于 K=256 时为头部保留空间，并让八个任务获得相同行数。

### 普通 `torch.mm` / `x @ y` FP32 路径

| 方阵大小 | 中位数 ms | 有效 GFLOPS | 有效 TFLOPS |
|---:|---:|---:|---:|
| 128 | 92.5853 | 0.04530 | 0.00004530 |
| 256 | 614.8185 | 0.05458 | 0.00005458 |

该路径包含有界分块、NPU 打包/副本、SHAVE 计算、结果选择与合并。完整输出通过 CPU FP64 参考校验。上表和单图表形状不同，不应直接相减以分解开销。

普通 Torch 的 FP16 `mm` 目前仍转换到 FP32 SHAVE 路径，最后转回 FP16；它不等于上面的 DPU FP16。当前 DPU FP16/低位能力通过冻结图与模型适配路径使用。

## 当前优化程度和解释边界

- 已有模型优化把多 token prefill 每层暖提交从 4 次减为 1 次；这属于模型图融合与运行时优化。本轮直接矩乘测试不衡量整层模型、训练或完整生成速度。
- DPU FP16 和 INT8 已能获得 TFLOPS/TOPS 量级的有效吞吐。增大 M 时吞吐明显上升，与更好摊薄固定开销、提高计算利用率相符；缺少设备时间戳和带宽/频率数据，不能精确划分计算、DMA、同步或 Python 占比。
- SHAVE FP32 即使排除输入构造、输出分配和合并后仍很慢。现有代码为标量点积、每次乘法后的补偿累加及 IEEE 分支，需要额外指令。其吞吐不能代表整个 NPU 的理论 FP32 能力，也不能与 DPU 原生低精度矩阵阵列峰值等同。
- 本轮最大的 DPU 权重、输入、输出各为 1,048,576 元素，达到当前 Tensor 存储上限。没有扩大边界来搜索芯片峰值，也没有测并发图、多队列、INT4 峰值或功耗。
